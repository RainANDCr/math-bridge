# MATH BRIDGE · 数学知识桥

**KARNAUGH MAP STUDIO｜卡诺图工作室**

[![Deploy to GitHub Pages](https://github.com/RainANDCr/math-bridge/actions/workflows/deploy.yml/badge.svg)](https://github.com/RainANDCr/math-bridge/actions/workflows/deploy.yml)

**在线访问：<https://rainandcr.github.io/math-bridge/>** —— 纯静态站点，没有后端，全部计算在你的浏览器里完成。

一个完全本地运行的交互式实验平台，把离散数学里的命题逻辑、数字电路里的卡诺图化简、概率论里的事件与随机实验，接到**同一个布尔函数对象**上。

输入一个表达式，你会同时得到：真值表、门级电路、卡诺图、最简与或式、以及在这个函数上的概率实验。改动其中任何一处，其余视图立刻同步 —— 因为它们本来就是同一件事的不同写法。

> 设计原则：先做正确、可验证的数学内核，再做交互。不为了视觉效果牺牲计算正确性。

同一个函数还可以在**五套学科记号**之间切换（离散数学 / 数字电路 / 布尔代数 / 集合论 / 概率论），
切换只改变写法，不改变真值表 —— 而且这个「不改变」由回读校验自动验证，不是口头承诺。

## 功能

### 01 逻辑工作台
- 表达式实时解析，语法错误**定位到具体字符**并给出修正方向
- 一键生成真值表（1–6 变量），支持 CSV 复制、行高亮、输出值编辑（0 / 1 / X）
- 七种逻辑门（AND / OR / NOT / XOR / NAND / NOR / XNOR）的符号、表达式与真值表
- 由表达式自动生成的**门级电路图**（标准 ANSI 门符号），点击输入端可直接给电路"通电"，观察信号逐级传播
- 表达式抽象语法树（AST）结构视图
- **符号模式切换**：同一个函数可在离散 / 数电 / 布尔 / 集合 / 概率五种记法间切换，
  面板同时给出该写法的适用语境；「全学科」模式把五种写法并排对照
- **冗余项与布尔除法**：最小覆盖之外还留着哪些"写得多余但删掉会改变函数"的项，
  以及把 `AB + AC + BC` 这类含共识项的和式除出 `A(B + C)` 的公因子；
  每个候选因子都给出「省几个文字 / 多几个门」的代价，不替你判断值不值

### 02 符号百科与逻辑门实验
- **8 种运算 × 5 个学科**的对照表：与、或、非、异或、同或、与非、或非、缓冲器
- 每个运算一张卡片，五种写法并排；点开右侧详情可看定义、真值表、标准门符号、易混淆点
- **搜索**支持中英文名称、符号与口语说法：搜 `AND` / `与` / `∧` / `·` / `交集` 都能找到「与运算」
- **输入识别器**：粘贴 `AB + C'`、`A NAND B`、`(A∩B)ᶜ` 等写法，显示被解析成什么、真值向量，
  以及「哪些符号按什么语境读」的说明
- **逻辑门实验**：八个门的标准 ANSI 符号（带输入/输出端子、反相圈、XOR 的额外弧线），
  切换 A/B 电平实时看输出；真值表高亮当前行；同一门给出五学科写法
- 不适用的对应会明确写「无直接对应」（例如缓冲器在集合与概率里没有对应运算），不硬凑

### 03 卡诺图工作室
- 2 / 3 / 4 变量卡诺图，行列严格使用格雷码（00, 01, 11, 10）
- 三种输入方式共用同一模型：**表达式**、**最小项 Σm/Σd**、**真值表逐格编辑**
- **输入区的符号按钮跟随当前记法**：数电下是 `· + ′ ⊕`，集合下是 `∩ ∪ ᶜ △`；
  取反是后缀，选中一段再点 `′` 会整体加括号（`A·B` → `(A·B)′`，而不是 `A·B′`）
  输入用撇号、渲染用上划线（`A′` 显示为 `A̅`）；式子里一出现取反，输入框下方就会说明这一点
  （说明里的示例走的是公式同一条渲染路径，不是把组合上划线字符拼进文案）——
  否则学生只会以为自己打错了
- 自动分组：枚举全部 3ⁿ 个立方体 → 提取素蕴含项 → 分支限界求**全局最优**覆盖
- 手动分组：点选格子 → 实时判定合法性（是否 2ᵏ 格、是否连续、是否选中了 0）→ 撤销/重做/清空
- 分组解释：该组覆盖哪些最小项、哪些变量不变（保留）、哪些变量变化（消去）
- SOP 与 POS 双形式，全部经过**逐行真值表比对**
- **化简推导**：Quine–McCluskey 逐步合并表，逐轮展示「哪两项只差一位 → 消去哪个变量」，
  再给出素蕴含项覆盖表（必需项 ★ / 最终采用高亮）；SOP 合并 1 格，POS 合并 0 格
- 显示 / 隐藏 minterm 编号、格雷码顺序切换、重叠分组按颜色与线宽区分
- **结果式与图内标签跟随符号模式**（离散 / 数电 / 布尔 / 集合 / 概率 / 全学科），
  切到集合模式时同一组 1 会写成 `A ∩ B ∪ Cᶜ`，而真值表与分组不变
- **冒险分析**：逐对检查卡诺图上相邻的两个 1 格（或两个 0 格）是否被**不同**的分组覆盖——
  是则切换瞬间会出现窄脉冲。给出「5 对相邻 1 格，全部安全」这样的逐项结论，
  并说明修复用的是共识项（`A·B + A·B̄` 补上 `A`），代价是最小覆盖不再是「最小」的那一份

### 04 多输出化简
- 同一组变量下的 2–4 个输出，一起化简
- **乘积项共享**：一个与门同时喂给多个输出；每个共享项在两幅卡诺图里同色
- **子表达式共享**：把共享粒度降到任意公共因子 —— `A·B·C + A·B·D` 提取出 `A·B`，
  两个输出都接它的输出（代数因式分解，生成 `T1 = A·B` 这样的定义序列）
- 两种粒度都有代价对比：门数、连线数、合计成本；同时说明「门少 ≠ 延迟小」
- 与「各自独立化简」并排对比，明确显示省了几个文字、几个乘积项

### 05 时序逻辑
- 状态转移表编辑（1–4 状态，1 位输入）
- **状态化简（等价状态合并）**：划分细化算法逐轮展示「哪一位输入把哪个块拆开」，
  应用前穷举全部长度 ≤ n 的输入序列，逐拍比对输出；化简可撤销
- **Moore 与 Mealy 两种输出模型**：Moore 只看状态，Mealy 的边标签带 `X/Z`
- **D 与 JK 两种触发器**：JK 由激励表反推 J/K，无关项参与化简，界面给出四行激励表
- **二进制与 one-hot 两种编码**：二进制穷举全部码字分配（3 状态 24 种、4 状态 24 种）；
  one-hot 每态一位，`D_i` 直接写成「进入该状态的转移之和」，并给出化简后的形式
- **四种组合的代价对比**：化简前 / 化简后 × 二进制 / one-hot，同一套计价规则真推导后并排比较；
  明确指出「状态数减少 ≠ 触发器减少」（4→3 在二进制下位宽不变，在 one-hot 下少一个触发器）
- 自动派生激励方程：把状态位 × 输入展开成真值表，交给同一套卡诺图最小化
- 状态图：节点、双向边、自环；点击节点可设为当前状态；1–3 状态用紧凑画布，窄屏不必横滚
- 逐拍模拟：设输入 → 点时钟 → 观察状态迁移与输出，历史逐拍可查
- 不可达状态检测：不可达 ≠ 无关项，界面上明确警告
- **竞争分析**：同步电路本身不看竞争（次态逻辑读的是沿前的稳定状态），所以这里查的是
  **时钟偏斜**下的情形——后采样的触发器可能看到「部分位已更新」的中间码。
  逐个多位变化列出中间码算出的次态，若与目标不同即判为**临界竞争**（会进错状态），
  全部相同则是**非临界竞争**（有竞争但无害）；中间码若不是合法状态，如实写「无法求值」而不当作振荡
- **偏斜裕量（门级延迟）**：把上面那条「可能」落到时间上——每个门 1 个时间单位延迟、触发器 0→Q 也是 1 个单位，
  只让一位的时钟晚到，逐位扫描偏斜，给出「从多少单位开始采错」。
  Q/D 波形如实画出跳变时刻与采样时刻，采样点按「采对 / 采错 / 正在跳变」着色。
  阈值不是拍的：它等于「时钟到输出 + 该位 D 端到被改位的组合路径」，所以**逻辑级数越浅，能忍的偏斜越大**
  （one-hot 的 D_i 只有两级，但它失败时会落进全 0 码 —— 所有 D_i 恒为 0，进去就出不来）
- **时序电路（由方程生成）**：把每个次态方程真的连成门——`输入 / 非 / 与 / 或 / 异或 / D 触发器 / 输出`，
  D 端接次态、Q 端把状态送回左侧。点「来一个时钟」会**同时采样所有 D**再统一更新，
  不是逐位算完就覆盖（否则后一级会看到已经变化的前级）；触发器的 D 端悬空会报错，不静默当成 0

### 06 门级搭建
- 拖拽节点、点端口连线：`输入 / 与 / 或 / 非 / 异或 / 输出`，与门可设 2–4 个输入
- **先有电路，再反推表达式**：从连线读出每个输出端的布尔表达式与真值表
- 结构检查：重复变量名、悬空输入、同一端口多驱动、组合环
- 与逻辑工作台的当前函数逐行比对，一致/不一致直接标出
- 网表文本一键复制；画布内容自动保存

### 07 概率实验室
- 每个输入变量的 P(X=1) 可调（滑块 + 数字输入）
- 理论概率解析计算，含无关项时的概率**区间**
- 蒙特卡洛模拟：100 / 1k / 10k / 100k 次，真实伪随机抽样，分批渲染不卡界面
- 固定随机种子可复现；收敛曲线带 ±2σ 理论波动带
- 理论值 vs 模拟频率对比、绝对误差、理论标准差
- **输入相关性建模**：把「输入独立」这个假设本身变成可调参数——直接编辑 2ⁿ 个输入组合的联合分布权重
  （内部归一化），一键回到「按当前边缘概率填满的独立模型」作对照
- 联合模型下重算 P(F=1)、逐对检查 P(X_i ∧ X_j) 与 P(X_i)·P(X_j) 的差（判断哪两个输入相关），
  蒙特卡洛也按联合分布抽样：先按权重抽一行，再查真值表，不是照着理论值造数据

### 08 知识连接实验室
- 三门课程的概念映射图（点击任意一行查看概念详解）
- 同一函数的六张联动卡片：表达式、命题解释、真值表、电路、卡诺图、概率
- **共享焦点行**：悬停真值表任意一行、或点击卡诺图格子，另一处同时亮起同一个最小项，
  顶部读数条给出它的变量取值、F 值、独立假设下的行概率，以及它被哪些分组覆盖
  （悬停是暂时的，点击会钉住，再点一次取消）
- **22 个概念**的详解：定义、形式化、直观解释、跨课程对应、可做的小实验、常见误区。
  覆盖命题/卡诺图之外，也含时序（状态机、编码、触发器、等价状态）、
  时序可靠性（竞争、时钟偏斜）、化简之外（静态冒险、冗余项、子表达式共享）、
  概率（事件、独立、联合分布、蒙特卡洛）

## 技术栈

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 构建 | Vite 5 | 秒级冷启动 |
| 框架 | React 18 + TypeScript 5 | 严格模式，`noUnusedLocals` / `noUnusedParameters` 全开 |
| 状态 | React Context + `useReducer` 风格不可变更新 | 无额外状态库 |
| 样式 | 结构化 CSS + 设计令牌（CSS 变量） | 无 UI 框架，深/浅两套主题 |
| 图标 | lucide-react | 仅图标 |
| 测试 | Vitest | 208 个用例，覆盖全部数学内核与符号系统 |
| 图表 / 电路 / 卡诺图 | 手写 SVG | 不依赖图形库，渲染完全可控 |

**没有后端、没有账号、没有在线 API、不依赖网络。** 所有数据存在浏览器 `localStorage`。

## 数学内核

### 1. 统一的函数模型

整个项目只有一个事实来源：

```ts
interface BooleanFunction {
  variables: string[];      // 有序，A 为最高位
  values: (0 | 1 | "X")[];  // 长度 2ⁿ，下标即最小项编号
  expression: string;       // 展示用表达式
  ast: BoolNode | null;     // 由表达式构造时保留
  source: "expression" | "minterms" | "table";
}
```

表达式、真值表、卡诺图、电路、概率全部由它派生。UI 层不含任何数学算法。

### 2. 解析

递归下降，优先级 `NOT > AND > XOR > OR`，同级左结合。变量统一为单个大写字母（A–H），小写自动转大写，支持 `A'` 后缀取反。错误以 `ExpressionError` 抛出，携带 `position`，界面据此高亮出错字符。

同时支持直接粘贴 `Σm(1,3,5) + Σd(2,6)` —— 三种输入方式实际上共用一个输入框。

### 3. 卡诺图映射

变量按 `A | B,C | C,D` 切分，行列都用格雷码序列 `i ^ (i >> 1)`：

| 变量数 | 布局 | 行 | 列 |
| --- | --- | --- | --- |
| 2 | 2×2 | A | B |
| 3 | 2×4 | A | B,C |
| 4 | 4×4 | A,B | C,D |

`cells[row][col] = 行值 << 列位宽 | 列值`。因为编号本身就是变量取值，**「相邻」等价于「二进制只差一位」**，四边环绕与四角分组自动成立，不需要任何特判。

### 4. 化简：为什么不是贪心

1. **枚举全部 3ⁿ 个立方体**（每位取 0 / 1 / 无关），保留完全落在 `1 ∪ X` 内的；
2. 过滤出**素蕴含项**（不能被更大的合法立方体包含）；
3. 选出「只被一个素蕴含项覆盖」的**必需项**；
4. 对剩余最小项做**分支限界精确覆盖**，按 `(乘积项数, 文字数)` 字典序取最优。

n ≤ 4 时立方体只有 81 个，n ≤ 6 时 729 个，枚举成本可忽略，换来的是**可证明的全局最优**，而不是"看起来还行"的贪心解。

对 POS，对 0 格（含 X）跑同一套算法，再用德摩根律把每个乘积项取反成和项 —— 两种形式共用一份经过验证的代码。

### 5. 化简推导：两套算法互相作证

界面上的「化简推导」不是把最终答案倒推成过程，而是独立跑了一遍 Quine–McCluskey：

- 第 k 轮把「只有一位不同、且该位仍固定」的两项合并，把该位写成 `-`；
- 没有任何配对可合并的项即为**素蕴含项**；
- 覆盖表列出每个素蕴含项覆盖的 1 格，只被一行覆盖的列就是**必需项**。

它与第 4 节的立方体枚举法是两条完全不同的路径（一条逐位合并，一条枚举 3ⁿ 个立方体），
却必须得到**同一批素蕴含项**。测试用 90 个随机 2–4 变量函数（含无关项）逐组比对，
任何一边写错都会立刻失败 —— 这比"两处都抄同一个答案"可靠得多。

### 6. 等价验证

化简结果不是"相信它"，而是**逐行比对**：把化简式重新对 2ⁿ 个输入求值，与原始真值表比较；无关项行不参与比对（它在设计上可以是 0 也可以是 1）。界面上显示的是"已在 N 行有效输入上逐一比对"的真实结果。

### 7. 电路生成

AST 中连续的同种运算会合并成一个多输入门（`A & B & C` 画成一个三输入 AND）。布局是分层树：叶子按出现顺序排开，门垂直居中于其输入，每列做一次防重叠推挤。点击输入端会重新求值整张网表，高电平连线点亮。

### 8. 多输出：共享乘积项的代价模型

各输出单独化简，得到的是「每个输出各自最简」，不是「总门数最少」。
一个乘积项若在两个输出里都出现，只需要造一次与门 —— 共享能省钱。

做法是把它当成一个带权集合覆盖：

1. 枚举对「至少一个输出」合法的立方体（`3ⁿ` 个）；
2. 每个立方体算出它能覆盖的 `(输出, 最小项)` 对；
3. 剔除被支配的立方体（覆盖是别人的子集、成本却不更低）；
4. 分支限界选一组覆盖全部对，最小化 `Σ(文字数 + 1)`，共享项只计一次。

代价里 `+1` 代表乘积项本身（与门输出）。这个模型解释了为什么共享项值得共用：
两个输出各造一个 2 文字项要 6，共享一个只要 3。

### 9. 时序：把状态转移表变回组合逻辑

Moore 状态机的输出只取决于当前状态。把状态用二进制编码后，
每个状态位配一个 D 触发器，`D = 次态`，于是：

- 次态方程 = 以「状态位 + 输入」为变量的布尔函数；
- 输出方程 = 以「状态位」为变量的布尔函数。

两者都直接交给第 4 节的精确最小化 —— 时序电路里没有新的化简算法，
它只是把同一套卡诺图用在了另一张真值表上。

状态图不可达 ≠ 无关项：不可达状态的转移仍然会被综合进电路，
把它当 X 会在某些上电初态下产生错误行为，所以界面只提示、不自动优化。

Mealy 型只是把输出方程多接一个输入变量：`Z = f(Q, X)`，其余流程完全相同。
JK 型则是把「要变成什么」换成「要怎么变」—— 由 `Q → Q⁺` 查激励表得到 `J/K`，
其中一半的组合是无关项（`Q=0` 时 K 随便，`Q=1` 时 J 随便），
再用同一套卡诺图化简。自检时按特性方程 `Q⁺ = J·¬Q + ¬K·Q` 回代，
能还原转移表才算通过 —— 只比对 J/K 表本身是不够的。

状态编码是同一台机器的另一种二进制命名。4 个状态只有 24 种编码，
这里全部真算一遍：相邻编码的两个状态在卡诺图上挨着，分组可能因此跨过它们，
方程就少几个文字。测试会验证「每种编码都还原同一台机器」。

### 10. 状态化简：划分细化，而不是「看着像就合并」

两个状态等价，指的是对**任意长度**的输入序列，从它们出发得到的输出序列完全相同。
不能只看转移表里相邻的两行像不像 —— 两个状态可能这一拍都输出 0，
下一拍却因为去向不同而分开。

算法是划分细化（partition refinement）：

1. 按输出分组 —— Moore 按 `Z`，Mealy 按 `(Z|X=0, Z|X=1)` 的二元组。
   输出不同的状态永远不可能等价。
2. 对每个组再检查：组内两个状态在同一个输入下的**次态落在哪个组**。
   比的是「次态属于哪个等价类」，不是次态编号 —— 编号本身没有意义。
3. 有组分裂就重来，直到稳定。此时每一组就是一个等价类。

界面把每一轮的分组与分裂依据都列出来，并明说是哪一位输入把块拆开的。
合并后的机器走同一套推导生成方程，再穷举长度 ≤ n 的全部 `2^(n+1)−1` 条输入序列逐拍比对输出。
长度 n 就够了：若两个状态可区分，最短区分序列不会超过状态数。

一个容易踩的坑：**状态数减少不等于触发器减少**。二进制编码下 4 → 3 仍然是 2 位，
只有跨过 2 的幂（4 → 2、8 → 5）才会少一个触发器；而 one-hot 的触发器数等于状态数，
所以同样一次 4 → 3，在 one-hot 下确实少一个。对比表把两种编码分开算，
就是为了不把这两件事混成一句「化简省了触发器」。

### 11. 子表达式共享：把粒度降到文字级

两级 SOP 只能共享整个乘积项。`A·B·C` 与 `A·B·D` 都含 `A·B`，
但整项不同就没法共用 —— 因式分解把 `A·B` 单独做成一个门：

```
T1 = A·B
T2 = C + D
F1 = T1·T2
```

代价怎么算是个陷阱。这里的规则必须对两种形式完全一致：

- **门数** = AND / OR 节点数（多输入算一个门）
- **连线数** = 所有门输入端子之和
- **文字数** = 其中直接接输入变量的端子（经典定义，仅作参考）
- **合计成本** = 门数 + 连线数（面积代理，不含延迟）

两个容易算错的地方：相同乘积项在两个输出里出现时只造一个与门（必须去重）；
单项乘积（如 `C`）不需要与门，它就是一根线。不按这两条算，会把基准抬高、虚报收益。

算法分两阶段：先在**所有输出的所有乘积项**之间提取公共文字子集（按收益从大到小），
再对每个输出递归「提公因子 → 分组 → 递归」；相同子问题通过签名缓存复用同一个节点，
得到的是 DAG 而不是树 —— 这正是共享的载体。

最后一定要比一次总成本：如果因式分解反而更贵，就退回两级形式。
「省了」不能靠局部公式宣布，得把整个电路造出来数一遍。

### 12. 门级网表：电路本身是可求值的对象

表达式工作台是「先写式子，再画电路」；门级搭建反过来。网表只有节点和连线：

1. **结构检查**：重复变量名、悬空输入、同一端口多驱动、组合环（Kahn 拓扑排序剩余即环）；
2. **求值**：按拓扑序逐节点算，`INPUT` 查赋值，`AND/OR/XOR` 折叠输入，`NOT` 取反；
3. **反推表达式**：从输出端递归回溯成 AST，再接回符号化简器与真值表。

第三步是关键：电路不是「表达式的一张插图」，它本身就能被求值。
把连线读回成表达式，才能证明「我搭的确实是我想要的」。
有任何一个端口没接，反推一律返回空 —— 不能把悬空端口悄悄丢掉，
否则会得到一个看似完整、实则错误的式子。

### 13. 符号系统：渲染即验证

符号系统不是「多画几种写法」，而是一条可检查的链路：

```text
用户输入 ──词法/语法──▶ AST ──渲染器──▶ 记号树 ──排版组件──▶ 屏幕
                         │                │
                         │                └── 文本 ──重新解析──▶ AST' ──逐行比对──▶ 一致 / 不一致
                         └── 真值表（唯一事实）
```

几个刻意的决定：

**1. 上划线必须结构化。** 记号树里 `bar` 是一个节点，不是一个字符。原因是
`¬(A·B)` 与 `¬A·¬B` 的文本回退长得很像，只有把「横线盖住哪些字符」变成树结构，
界面才能画对，测试才能断言对。纯文本复制时退回「括号 + 撇号」，这一点在界面注明。

**2. 五个学科共用同一套括号规则。** 各学科只提供字形表（`and` / `or` / `xor` / `not` 的符号与形式），
括号放在哪里由同一段代码决定。如果每个学科各写一份，很容易出现某一种写法少一层括号，
而两种写法在真值表上仍然等价 —— 这种错误不会自己暴露。

**3. 回读校验是界面上的真实数字。** 符号面板右上角的「回读校验 5/5」不是装饰：
它把渲染出来的文本重新交给解析器，与原始 AST 在每个最小项上比对。任何一次渲染回归都会让它变红。

**4. 别名按上下文解析，不做字符串替换。**

| 输入 | 读法 | 为什么不能全局替换 |
| --- | --- | --- |
| `A'` / `A′` / `Aᶜ` / `A̅` | 后缀取反，只作用于紧邻对象 | `A·B′` 是 `A·(¬B)`，`(A·B)′` 才是 `¬(A·B)` |
| `AB` / `A(B+C)` | 隐式与，**只**在 AND 层生效 | 否则 `A + BC` 会被读成 `(A+B)·C` |
| `A AND B` | 词形运算符，只在「运算符该出现的位置」识别 | `AND` 本身是 A、N、D 三个合法变量名 |
| `A NAND B` | 先与后非 | 不是 `(¬A) ∧ B` |
| `A ⊙ B` / `A ↔ B` | 同或 | 与异或字形相近，语义相反 |

**5. 概率模式只写事件表达，不代入数字。** `P(A ∩ B)` 与 `P(A)·P(B)` 只有在独立时才相等，
独立性是额外条件，推不出来。界面把「需要哪些条件」直接列在公式下面。

验收函数 `F = (A & B) | !C` 在五种记法下的输出：

| 记法 | 教材写法 | 简写写法 |
| --- | --- | --- |
| 离散数学 | `A ∧ B ∨ ¬C` | <code>A&B&#124;~C</code> |
| 数字电路 | `A·B + C̅`（横线盖住 C） | `AB+C′` |
| 布尔代数 | `AB + C′` | `AB+C′` |
| 集合论 | `A ∩ B ∪ Cᶜ` | `A∩B∪Cᶜ` |
| 概率论 | `P(A ∩ B ∪ Cᶜ)` | `P(A∩B∪Cᶜ)` |

### 14. 冒险：化简保证稳态，冒险发生在切换瞬间

化简只对「输入稳定之后输出是什么」负责。输入从一格移到相邻一格时，两个格子在
**纸面**上属于同一组，在**电路**里却可能落到两个不同的与门，谁的延迟大谁后到，
中间那一段输出就可能掉一下 —— 这就是静态-1 冒险（SOP）。

判据落到卡诺图上很直接：两个相邻的 1 格如果**没有同一项同时覆盖**，就有冒险。
修复也直接从图上读：两者的共识项（只差一个文字的两项，其公共部分）正好同时覆盖这一对格，
补上它即可。代价要写清楚 —— 加上共识项之后，覆盖不再是「最小」的那一份，
**所以「最小化」与「无冒险设计」是两个目标，不是同一个**。

POS 方向同理，但看的是 0 格与或项。

不做的部分也写在界面上：功能冒险（多个输入同时变化，前后函数值不同）与动态冒险
（需要三条以上不同延迟路径）不在两格相邻的判据里，前者加项消不掉，后者要有时延模型。

### 15. 竞争：同步设计本身不看竞争，看的是时钟偏斜

同步电路里所有触发器在同一个沿采样，次态逻辑读到的是沿前的稳定状态，
所以**理想同步设计不存在竞争**。真正的问题是时钟偏斜：后采样的那一位可能看到
「部分位已经更新」的中间码。

于是判据是一次性的，不做电平迭代：对每个多位变化，列出「只有部分位已到」的每一个中间码，
用中间码算一次次态。

- 中间码算出的次态 ≠ 目标 → **临界竞争**，可能进错状态
- 全部中间码都算到目标 → **非临界竞争**，有竞争但无害
- 中间码本身不是合法码（one-hot 少一位）→ 没有定义，如实写「无法求值」，不当作振荡

第一版把竞争写成电平异步迭代，结果把普通计数器判成了震荡 —— 计数器在异步模型下确实会
在中间码之间来回，但同步电路不按那个方式工作。判据错了，结论必然错。

### 16. 布尔除法：最小覆盖之外的那些项

最小覆盖是「用最少的项覆盖所有 1」，但它不等于「没有多余的项」。
`AB + AC + BC` 里 `BC` 在覆盖上可能是必需的，在代数上却是共识项 —— 删掉它整式的值不变，
这正是它的危险之处（也是静态-1 冒险的温床）。

布尔除法的做法是先剪掉这类共识冗余项，再按 `F = D·Q + R` 求解商：

- 除数为 1 时，商就是被除式的余因子（把除数的文字代入并化简）
- 除数为 0 的那些行，商是无关项 —— 正是这些无关项让 `A + C` 成为 `(A+C)·(C+B)` 的因子

代价按「文字数 + 门数」粗估，界面把商与代价一起摆出来，不替你判断值不值得。

### 17. 输入相关性：把「独立」变成可调参数

概率实验室默认 `P(x) = Π P(X_i = x_i)`。这个假设很方便，但它不是逻辑的必然：
A 与 B 完全可能同涨同落，此时 `P(A∩B) ≠ P(A)·P(B)`，输出的概率也会变。

联合模型直接给出 2ⁿ 个组合的权重（内部归一化），独立模型是它的一个特例
（权重恰好等于边缘概率之积）。于是可以做一件很有说服力的事：
**保持边缘概率不变，只改相关性，看 P(F=1) 变不变** —— 变了就证明「边缘概率推不出相关性」。

蒙特卡洛也按联合分布抽样：先按权重抽一行，再查真值表。抽的是真实分布，
不是照着理论值造数据；同一个种子仍可复现。

### 18. 时序电路：方程真的连成门

到这里时序设计不再停在方程。每个次态方程的乘积项连成与门、各项连成或门，
D 端接次态、Q 端把状态送回左侧 —— 这是真实的反馈，不是画上去的箭头。

两个实现上的关键点：

**1. D 触发器不参与组合环判定。** Q 的值来自状态表而不是网表求值，
所以反馈线在拓扑排序里不构成环；否则任何带反馈的时序电路都会被判成「有环」。

**2. 时钟是同时采样，不是逐位覆盖。** 点一次时钟，先把所有 D 端的值算出来存下，
再统一写回状态。逐位算完就写回的话，后面那一位会读到已经变化的前级 —— 那是另一台机器。

JK 触发的机先按次态值折算成 D 再接入，行为与原状态机逐拍一致（测试逐个状态、逐个输入验证过）。

### 19. 偏斜裕量：把「可能」变成「多少单位之后」

第 15 节的竞争分析有个说不出口的含糊：它默认中间码会**稳定地**出现在采样时刻。
但中间码要多久才形成？采样又发生在什么时候？没有时间就没有答案。

于是把网表接上时间，做一次事件驱动的仿真：

- 每个门 1 个单位延迟，触发器「时钟沿 → Q 变化」1 个单位，布线延迟忽略；
- 只有一位的时钟晚到 δ，其余同时；
- 某个节点变化后，它驱动的门在 1 个单位后重算；同一时刻到达的多条输入**一起**看，
  否则会凭空造出并不存在的毛刺；
- 短于一个门延迟的毛刺被吞掉（惯性延迟）—— 这也是真实门的脾气。

采样点取在「后采样那一位的时钟沿」，看它此刻采到的是 0 还是 1。
如果正好有一条跳变落在这一 tick，就记「正在跳变」而不是猜一个值。

**阈值是可以推出来的，不是扫出来的。** 偏斜小于

```text
时钟到输出 + 从被改的那一位到该位 D 端的组合路径延迟
```

时，采样发生在跳变传到 D 端之前，采到的仍是沿前的值。逐位扫描只是把这个数**量**出来并附上波形，
所以「逻辑级数越浅越抗偏斜」这句话在这里是可以验算的，不是口号。

两处容易写错的地方：

**1. 第二遍仿真。** 第一遍假设每位都采到正确值，据此画出波形；如果晚采样那位其实采到了错值，
它的 Q 就不该按正确次态跳变，需要用它真正采到的值重跑一遍。这一遍不会改变任何采样结论 ——
所有采样都不晚于 δ，而被改动的 Q 跳变发生在 δ + 时钟到输出，因果上在后面。收敛是有保证的。

**2. 扫描范围要越过阈值一点。** 只扫到阈值处，看到的永远是「正好卡在跳变」那一刻，
看不到「稳定地采到错值」那一段 —— 而后者才是真正会停在错误状态上的情形。

## 概率计算的两个前提

界面里也明确标注了，这里再写一次：

1. **各输入变量相互独立。** 因此

   $$P(x) = \prod_i P(X_i = x_i), \qquad P(F=1) = \sum_{x: F(x)=1} P(x)$$

   若变量之间存在关联，必须使用条件概率，不能直接相乘。概率实验室的「输入相关性」面板
   可以放弃这个假设：改成直接给出联合分布后，P(F=1) 按联合权重求和，
   并与「同样的边缘概率、假设独立」的结果并排对比。

2. **每个变量只有 0 / 1 两个取值。** 所以 `P(X=0) = 1 − P(X=1)`。

3. **含无关项时概率是区间，不是定值。** 下界把所有 X 当 0，上界把所有 X 当 1；模拟按 X=0 处理，界面会同时给出区间。

模拟使用 mulberry32 可播种伪随机数发生器，每次试验都真的抽取 n 个均匀随机数再查真值表。10 万次模拟按帧分批执行（每帧约 1/40），因此不会冻结界面；给定的种子可以完全复现同一组结果。

  one-hot 的失败码是全 0 且全 0 是吸收态（所有 D_i 恒为 0）

## 已知限制与后续计划

**限制**

- 卡诺图支持 2–6 变量；7 个以上变量纸面已无法直视，只保留化简结果。
- 合并表（Quine–McCluskey 推导）只对 2–4 变量展开，5–6 变量给出结果但不逐轮列表。
- 多输出化简界面上限 4 个输出、4 个变量；内核同样支持到 6 变量，但搜索规模会明显上升。
- 时序逻辑界面最多 4 个状态、1 位输入；8 状态的编码空间是 40320 种，界面未做穷举（内核可算，但会明显变慢）。
- 竞争分析有两层：状态层按「一次采样看到部分已更新的位」判定，中间码若落在非法码字（one-hot 少位）上，
  只能如实写「无法求值」；门级层用单位延迟仿真给出阈值，但这个延迟模型是**教学用的**：
  每个门都一样快、不含扇出与布线差异，也不设建立/保持窗口——所以「正好卡在跳变」只出现在一个刻度上，
  真实器件那里是一段宽度有限的亚稳态窗口。
- 偏斜只按「一位晚到、其余同时」扫描。整组时钟一起偏斜是一阶效应（不改变相对时序），
  但两位以上以不同偏斜乱序到达的情形没有覆盖。
- 冒险分析只查相邻两格的静态冒险（SOP 的静态-1、POS 的静态-0）；功能冒险与动态冒险不在判据内。
- 时序电路的网表不含时钟树、复位与总线；触发器 D 端悬空会报错，但网表本身用于观察与教学，不追求可综合。
- one-hot 没有可选的码字分配（每态一位），因此不做编码搜索；它的方程仍按同一套文字数计价，
  没有按「一级与或、扇入固定」的浅层结构单独折算延迟。
- 子表达式共享做代数因式分解（公共文字子集），布尔除法单独成面板，两者没有合并成一次搜索；
  成本模型不含延迟。
- 门级搭建只支持组合电路；不含触发器、时钟与总线，也不支持多输出以外的层次化封装。
  （时序电路的门级视图由方程自动生成，不接受手工连线。）
- 最小化器有 20 万节点上限；若触发会在界面明确提示"可能不是全局最优"，不会伪装成最优解。2–4 变量下从未触发。
- 输入相关性按联合分布建模（2ⁿ 个权重），不做贝叶斯网络或条件概率表的多层依赖。
- 无关项参与概率计算时按 X=0 模拟。
- 符号系统只覆盖「同一个布尔结构」能表达的五种语境。蕴含（→）、量词、模运算等不在其中；
  遇到不适用的情况会写「无直接对应」，不会硬造对应关系。
- `⊙` / `↔` 只在布尔语境下读作同或；若把它们当作文本里的普通符号，会被当成运算符。
- 双重取反不做化简（`¬¬A` 照实显示成两层横线），因为化简会改变 AST 的结构展示；
  真值表不受影响。
- 纯文本复制时上划线统一退回「括号 + 撇号」，这是刻意的：把每个字符都加上划线会变成
  `¬A·¬B`，与 `¬(A·B)` 语义相反。
- 概率模式的表达式只描述事件结构；具体数值仍由概率实验室按「输入独立」的模型计算。
